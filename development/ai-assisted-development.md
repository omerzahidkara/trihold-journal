# AI-assisted development without the hype

Modern AI tools are part of why I decided to attempt this solo RTS project. They help with programming, exploring unfamiliar technologies, reviewing decisions, building validation scaffolding and documenting work.

They do not automatically produce a good game.

The person developing the project remains responsible for the design, maintainability, security boundaries, technical debt, validation and final player experience. Writing a test is not the same as running it; passing a bounded test is not the same as proving a stable multiplayer product; producing many features is not the same as creating meaningful strategy.

I try to distinguish **planned design**, **implemented code**, **automated validation**, **manual observations** and **claims requiring real player evidence**. Those are different levels of confidence.

This public journal intentionally focuses on game decisions and the journey. Private implementation files and internal task documents are not mirrored here.

My goal is to use new tools to attempt something ambitious, while remaining clear-eyed about the difficult work they cannot replace.
